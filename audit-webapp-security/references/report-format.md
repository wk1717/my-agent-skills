# 보안 감사 보고 형식

## 1. 발견사항 채택 기준

다음이 모두 존재할 때 발견사항으로 채택하라.

- 신뢰 경계를 넘는 공격자 제어 입력
- 실제 코드·설정 경로
- 누락되거나 우회 가능한 방어
- 구체적인 보안 영향
- 재현 또는 합리적인 공격 시나리오

근거가 부족하면 `확인 필요`, 모범 사례 차이는 `하드닝 제안`으로 분리하라.

## 2. 심각도

### P0 · 긴급

기본 또는 현실적인 배포에서 비인증 원격 공격자가 광범위한 시스템 장악, 대규모 민감정보 탈취, 임의 코드 실행, 치명적인 금전 피해를 즉시 일으킬 수 있음.

### P1 · 높음

인증 우회, 관리자 권한 상승, 다른 조직·사용자의 고민감 데이터 접근, 지속적인 계정 탈취, 중대한 비즈니스 무결성 훼손이 현실적인 조건에서 가능함.

### P2 · 중간

제한된 데이터 노출·변조, 특정 조건의 권한 우회, 악용 가능한 CSRF·XSS·SSRF, 서비스 가용성 저하처럼 의미 있는 영향이 있지만 전제·범위가 제한됨.

### P3 · 낮음

영향이 작거나 여러 강한 전제가 필요하지만 실제 공격 경로가 존재함.

### 하드닝

현재 공격 경로가 입증되지 않았으나 방어 심도, 탐지, 운영 복원력을 높이는 개선.

심각도는 `공격 난이도 × 필요한 권한 × 영향 범위 × 데이터 민감도 × 탐지·복구 가능성`을 함께 고려하라. 불확실성을 높게 잡아 심각도를 부풀리지 마라.

## 3. 신뢰도

- `높음`: 코드 경로와 방어 부재를 직접 확인하고 안전하게 재현함
- `중간`: 정적 경로는 확실하나 배포 설정 또는 런타임 전제가 남음
- `낮음`: 의심 신호는 있으나 도달 가능성 또는 영향이 확인되지 않음

낮은 신뢰도의 항목은 원칙적으로 발견사항 대신 확인 필요에 배치하라.

## 4. 최종 응답 순서

### 결론

가장 중요한 결과를 3~6문장으로 먼저 제시하라. 긴급 차단이 필요한 항목, 전체 위험도, 감사 한계를 포함하라.

### 범위와 방법

- 검토한 애플리케이션·서비스·경로
- 정적 분석, 테스트, 로컬 동적 검증 여부
- 사용한 역할·공격자 모델
- 제외되거나 접근하지 못한 범위

### 발견사항

심각도순으로 작성하라. 발견사항이 없으면 그렇게 말하되 검토 범위와 미검증 영역을 함께 명시하라.

각 발견사항은 다음 형식을 사용하라.

```text
[P1] 객체 소유권 확인 없이 다른 사용자의 파일 다운로드 가능

신뢰도: 높음
분류: CWE-639 / OWASP API1
영향 범위: 다운로드 API와 공유 링크

근거:
- path/to/controller.ts:120 — 요청 ID로 파일을 조회하지만 소유자 조건이 없음
- path/to/service.ts:88 — 조회 결과를 추가 권한 검사 없이 반환

공격 경로:
1. 일반 사용자 A가 자신의 파일 URL에서 UUID 형식을 확인
2. 사용자 B의 노출된 파일 ID를 다운로드 API에 전달
3. 서버가 사용자 B의 파일을 반환

영향:
다른 사용자의 계약서와 개인정보가 노출될 수 있음.

수정:
파일 조회 조건에 조직·소유자 범위를 포함하고 관리자 예외를 명시적으로 검사.

검증:
사용자 A의 토큰으로 사용자 B 파일 요청 시 403, 자신의 파일은 200인지 통합 테스트.
```

### 하드닝 제안

실제 취약점과 섞지 말고 기대 효과와 우선순위를 짧게 적어라.

### 확인 필요와 잔여 위험

- 접근하지 못한 운영 설정
- 실행하지 못한 네트워크 의존 감사
- 테스트 계정 부재로 확인하지 못한 역할
- 제3자 콘솔·클라우드 IAM·WAF처럼 저장소 밖의 통제

### 실행한 검증

명령 또는 테스트 묶음과 성공·실패 결과를 요약하라. 긴 로그를 붙이지 마라.

## 5. 코드 리뷰 출력 규칙

- 파일과 1부터 시작하는 정확한 줄 번호를 사용하라.
- 한 발견사항의 줄 범위는 핵심 원인에만 좁게 잡아라.
- 결과 증상이 아니라 수정 가능한 근본 원인에 코멘트를 붙여라.
- 같은 원인의 반복 사례는 대표 위치에 코멘트하고 나머지 영향을 본문에 나열하라.
- 정상 동작이나 칭찬용 코멘트를 만들지 마라.
- 취약하지 않은 추측에는 인라인 코멘트를 붙이지 마라.
