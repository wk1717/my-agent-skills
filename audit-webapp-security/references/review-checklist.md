## 1. 아키텍처와 신뢰 경계

- 인터넷, 브라우저, 앱 서버, 워커, DB, 객체 저장소, 외부 SaaS 사이 경계를 표시하라.
- 각 입력점의 파서, 인증, 권한, 속도 제한, 출력 위치를 추적하라.
- 관리자 전용 네트워크나 내부 API가 실제로 외부에서 차단되는지 확인하라.
- 프록시 헤더, 실제 클라이언트 IP, TLS 종료 지점을 신뢰하는 조건을 확인하라.
- 개발용 엔드포인트, 헬스체크, 메트릭, API 문서, 디버그 콘솔의 노출을 확인하라.

## 2. 인증과 계정 수명주기

- 비밀번호 해시는 검증된 KDF와 적절한 비용을 사용하는지 확인하라.
- 로그인 아이디 존재 여부, 잠금 여부, 실패 원인이 과도하게 노출되지 않는지 확인하라.
- 로그인 시도 제한이 사용자 키와 IP 키 양쪽을 고려하는지 확인하라.
- 로그인뿐 아니라 비밀번호 변경, 민감 문서 발급, 관리자 재인증처럼 현재 비밀번호를 다시 검증하는 모든 경로에 시도 제한이 일관적인지 확인하라.
- 비밀번호 변경·초기화 시 현재 세션과 기존 토큰을 폐기하는지 확인하라.
- 초대·초기 비밀번호·이메일 변경·MFA 복구 흐름의 소유권 증명을 확인하라.
- 비활성·퇴사·삭제 계정이 즉시 접근을 잃는지 확인하라.
- 관리자 수가 0이 되거나 마지막 관리자가 스스로 권한을 잃는 경계를 확인하라.
- 계정 연결과 SSO에서 이메일 문자열만으로 계정을 합치지 않는지 확인하라.

## 3. 세션과 토큰

- 쿠키에 `HttpOnly`, `Secure`, 적절한 `SameSite`, 좁은 `Path`가 적용되는지 확인하라.
- 세션 고정 방지를 위해 로그인·권한 상승 시 식별자를 회전하는지 확인하라.
- 액세스·리프레시 토큰의 수명, 발급자, 대상, 알고리즘, 키 회전을 확인하라.
- 토큰 검증에서 알고리즘 혼동, `none`, 약한 기본 키, 만료 미검증이 없는지 확인하라.
- 로그아웃·비밀번호 변경·권한 변경 후 기존 토큰이 계속 유효한지 확인하라.
- 토큰을 URL, 로그, localStorage, 오류 메시지에 노출하지 않는지 확인하라.
- 동시 세션과 장기 미사용 세션에 대한 정책을 확인하라.

## 4. 권한과 객체 접근

- 모든 민감 API에 서버 측 인증과 역할 검사가 적용되는지 확인하라.
- 객체 ID를 받은 뒤 소유자·프로젝트·테넌트 범위를 함께 조건으로 조회하는지 확인하라.
- 생성·조회·수정·삭제·내보내기·복구마다 권한이 일관적인지 확인하라.
- 목록에서는 숨기지만 상세 조회가 가능한 IDOR이 없는지 확인하라.
- 부모 자원 권한 없이 하위 자원 ID만으로 접근할 수 없는지 확인하라.
- 대량 작업과 검색 API가 단건 API보다 넓은 데이터를 반환하지 않는지 확인하라.
- 클라이언트가 보낸 역할·소유자·가격·상태 필드를 그대로 신뢰하지 않는지 확인하라.
- 관리자 대행·사칭 기능의 재인증, 표시, 감사 로그를 확인하라.

권한 행렬에는 최소 `비인증`, `일반 사용자`, `다른 사용자`, `팀장`, `관리자`, `외부 계정`, `비활성 계정`을 포함하라.

## 5. 입력 검증과 인젝션

- 유효성 검증이 허용목록, 길이, 타입, 범위, 중첩 깊이를 제한하는지 확인하라.
- 검증과 사용 사이에 정규화 차이가 없는지 확인하라.
- SQL·NoSQL·LDAP·GraphQL 쿼리가 매개변수화되는지 확인하라.
- 셸 명령, 템플릿, 정규식, XPath, 로그 문자열에 사용자 입력이 합성되는지 확인하라.
- 대량 배열, 큰 본문, 재귀 JSON, 압축 폭탄으로 자원 고갈이 가능한지 확인하라.
- 정수 오버플로, 음수 금액, 부동소수점 정밀도, 시간대 경계를 확인하라.
- 역직렬화 대상 타입과 프로토타입 오염 가능성을 확인하라.
- CSV·스프레드시트 내보내기에서 수식 인젝션을 확인하라.

## 6. 브라우저와 프론트엔드

- HTML 삽입, Markdown, 리치 텍스트, SVG, 이메일 미리보기에 출력 인코딩·정화가 있는지 확인하라.
- `dangerouslySetInnerHTML`, DOM sink, URL 기반 렌더링을 추적하라.
- 상태 변경 요청에 CSRF 방어 또는 안전한 SameSite 전략이 있는지 확인하라.
- `SameSite`만 신뢰하지 말고 같은 사이트의 다른 서브도메인 공격을 포함해 `Origin`, `Referer`, `Sec-Fetch-Site`, 커스텀 헤더 중 실제 출처 검증 계층을 확인하라.
- 상태 변경 GET, 최상위 탐색, multipart/form 요청처럼 CORS preflight 없이 도달하는 경로를 따로 찾으라.
- CORS가 자격증명과 와일드카드 출처를 함께 허용하지 않는지 확인하라.
- CSP, 클릭재킹 방지, MIME 스니핑 방지, Referrer Policy를 확인하라.
- 공개 응답과 개인정보 응답의 캐시 지시자가 구분되는지 확인하라.
- 외부 링크에 `noopener`, 안전한 프로토콜 검증, 오픈 리디렉션 방지가 있는지 확인하라.
- 소스맵, 환경변수, 서버 전용 비밀이 클라이언트 번들에 포함되지 않는지 확인하라.
- UI 권한 숨김과 별개로 API 권한이 존재하는지 확인하라.

## 7. API·웹훅·실시간 통신

- API 버전·콘텐츠 유형·본문 크기·필수 헤더를 검증하는지 확인하라.
- 오류 응답이 스택, SQL, 내부 경로, 비밀정보를 노출하지 않는지 확인하라.
- GraphQL의 깊이·복잡도·인트로스펙션 정책을 확인하라.
- WebSocket 연결과 구독 채널마다 인증·객체 권한을 재검증하는지 확인하라.
- 웹훅 서명을 원문 바이트로 검증하고 시간 허용폭과 재전송 방지를 두는지 확인하라.
- 이벤트 ID·요청 키로 중복 처리를 막는지 확인하라.
- 페이지네이션 상한과 필터 권한이 있는지 확인하라.
- 레이트 리밋이 프록시 우회와 분산 키를 고려하는지 확인하라.

## 8. 외부 요청과 SSRF

- 사용자가 URL, 호스트, 리디렉션, 포트, 프로토콜을 통제하는 모든 요청을 찾으라.
- DNS 재바인딩, 사설·루프백·링크로컬·메타데이터 IP를 차단하는지 확인하라.
- 최초 URL뿐 아니라 모든 리디렉션 목적지를 재검증하는지 확인하라.
- `file:`, `gopher:`, `ftp:` 등 불필요한 프로토콜을 차단하는지 확인하라.
- 연결·읽기 시간 제한, 응답 크기 제한, 허용 콘텐츠 유형을 확인하라.
- 프록시·웹훅 테스트·URL 미리보기·이미지 가져오기 기능을 함께 확인하라.

## 9. 파일과 미디어

- 파일명과 저장 경로를 서버가 생성하고 경로 순회를 차단하는지 확인하라.
- 확장자·MIME 헤더뿐 아니라 매직 바이트 또는 안전한 디코더로 내용을 검증하는지 확인하라.
- 파일 개수·개별 크기·전체 크기·압축 해제 크기를 제한하는지 확인하라.
- 업로드를 실행 가능한 웹 루트 밖에 저장하고 다운로드 시 안전한 헤더를 설정하는지 확인하라.
- SVG·HTML·PDF·Office·압축 파일의 활성 콘텐츠 위험을 확인하라.
- 미리보기·썸네일 변환기의 취약한 네이티브 라이브러리와 샌드박스를 확인하라.
- 다운로드·삭제·공유 링크에 객체 권한과 만료가 적용되는지 확인하라.
- 고아 파일, 실패한 트랜잭션, 바이러스 검사 전 공개 상태를 확인하라.

## 10. 데이터베이스와 개인정보

- 최소 수집, 목적 제한, 보존 기간, 삭제·익명화 경로를 확인하라.
- 주민번호, 급여, 건강, 인증문서 등 고민감 데이터를 분류하라.
- 민감 컬럼의 저장 암호화, 키 분리, 응답 최소화를 확인하라.
- ORM 엔티티 전체 직렬화로 해시·토큰 버전·내부 필드가 새지 않는지 확인하라.
- 모든 eager 관계와 엔티티 spread·직접 반환을 전수 목록화하고, 목록·상세·생성·수정 응답이 동일한 최소 직렬화 함수를 통과하는지 확인하라.
- 백업·복제·분석 환경·개발 시드에 운영 개인정보가 복사되는지 확인하라.
- 마이그레이션의 기본값, nullability, 외래키, 삭제 정책이 보안 경계를 약화하지 않는지 확인하라.
- 사용자·프로젝트 삭제 시 최신 엔티티까지 포함한 FK 영향 그래프를 만들고 self-FK, 작성자 보존, 감사 기록, 외부 파일 소유권을 함께 확인하라.
- 소스 엔티티 선언과 적용 DB가 같다고 가정하지 말고 가능하면 실제 제약의 `delete_rule`, nullability, pending migration을 확인하라.
- 직접 객체 참조와 순차 식별자가 정보 노출을 키우는지 확인하라.
- 트랜잭션 밖 상태 변경으로 부분 적용이 가능한지 확인하라.

## 11. 비밀정보와 암호화

- 저장소·히스토리·빌드 로그·컨테이너 이미지·클라이언트 번들의 비밀 노출을 확인하라.
- `.env` 원문을 출력하지 말고 키 이름과 파일 추적 여부만 확인하라.
- 기본 키, 샘플 키, 짧은 JWT 키, 고정 IV·nonce가 없는지 확인하라.
- 검증된 라이브러리와 인증된 암호화 모드를 사용하는지 확인하라.
- 키의 환경 분리, 접근 권한, 회전, 폐기, 버전 관리를 확인하라.
- 비교가 필요한 서명·토큰에 상수 시간 비교가 필요한지 확인하라.
- 난수와 UUID가 보안 용도에 충분한 생성기를 사용하는지 확인하라.

## 12. 비즈니스 로직과 남용

- 가격, 수량, 할인, 급여, 연차, 승인 상태를 서버가 재계산하는지 확인하라.
- 허용된 상태 전이와 역전·재승인·재발송 조건을 확인하라.
- 자기 승인, 순환 승인, 관리자 수 제한, 한도 우회를 확인하라.
- 여러 작은 요청으로 일·월 한도를 우회할 수 있는지 확인하라.
- 삭제·취소·환불 후 자원과 권리가 함께 복원·회수되는지 확인하라.
- 초대, 알림, 메일, 내보내기를 스팸·정보 탐색에 악용할 수 있는지 확인하라.
- 시간·날짜·윤년·타임존 경계에서 권리나 금액이 중복되는지 확인하라.

## 13. 경쟁 상태와 중복 처리

- 읽기 후 쓰기 사이 TOCTOU, 이중 제출, 병렬 승인, 재고·잔액 경쟁을 확인하라.
- DB 잠금, 유일 제약, 원자적 갱신, 낙관적 버전 중 적절한 방어가 있는지 확인하라.
- 외부 API 성공 후 DB 실패와 DB 성공 후 외부 API 실패를 구분하라.
- 웹훅·큐·메일·재시도 작업이 멱등성을 갖는지 확인하라.
- 요청 취소·타임아웃 후 작업이 계속 실행될 때 중복을 막는지 확인하라.

## 14. 의존성·빌드·공급망

- 잠금파일이 존재하고 재현 가능한 설치를 사용하는지 확인하라.
- 사용 중인 패키지 관리자 기준으로 감사하되 잠금파일을 변경하지 마라.
- 외부 감사 서비스는 의존성 메타데이터를 전송할 수 있으므로 도구 승인·사용자 권한을 확인하고, 차단되면 우회 전송하지 말고 미검증 범위로 명시하라.
- 직접 의존성뿐 아니라 전이 의존성의 도달 가능성을 확인하라.
- 설치 스크립트, Git·로컬 경로 의존성, 비고정 버전, 이름 유사 패키지를 확인하라.
- CI 액션·컨테이너 베이스 이미지를 불변 digest 또는 신뢰 가능한 버전으로 고정하는지 확인하라.
- 빌드 시 비밀이 이미지 레이어·캐시·산출물에 남는지 확인하라.
- 생성 산출물·소스맵·테스트 fixture에 비밀이 없는지 확인하라.

## 15. 배포·인프라·클라우드

- 운영에서 디버그·자동 스키마 동기화·개발용 CORS가 꺼지는지 확인하라.
- TLS, HSTS, 프록시 신뢰, 호스트 헤더 검증을 확인하라.
- DB·캐시·관리 포트가 공개 네트워크에 노출되지 않는지 확인하라.
- Compose·개발 기본 포트의 실제 host bind(`0.0.0.0` 대 `127.0.0.1`)와 기본 자격증명 조합을 렌더된 설정으로 확인하라.
- 서비스 계정과 IAM이 최소 권한인지 확인하라.
- 객체 저장소 버킷, 서명 URL, CDN 캐시의 공개 범위를 확인하라.
- 컨테이너가 비루트, 읽기 전용 파일시스템, 제한된 capabilities로 실행되는지 확인하라.
- 운영 환경변수 미설정 시 안전하게 실패하는지 확인하라.
- 비밀 파일이 ignore되는지만 보지 말고 로컬 파일 권한이 다른 OS 사용자에게 읽기 가능하지 않은지 메타데이터만 확인하라.
- 마이그레이션·롤백·키 회전 중 구버전과 신버전의 호환성을 확인하라.

## 16. 로그·오류·감사·복구

- 로그에 비밀번호, 토큰, 쿠키, 주민번호, 급여 상세, 파일 원문이 없는지 확인하라.
- 보안 이벤트에 행위자, 대상, 시각, 결과, 상관 ID가 남는지 확인하라.
- 감사 로그를 일반 사용자가 수정·삭제할 수 없는지 확인하라.
- 인증 실패·권한 상승·대량 내보내기·웹훅 실패를 탐지할 수 있는지 확인하라.
- 사용자 오류와 내부 오류를 분리하고 내부 상세를 외부에 노출하지 않는지 확인하라.
- 백업 복원, 파일 복구, 키 분실, 관리자 잠금 상황의 복구 절차를 확인하라.

## 17. 외부 연동과 OAuth

- OAuth `state`, PKCE, 정확한 redirect URI, nonce를 사용하는지 확인하라.
- 토큰을 서버 측에 암호화 저장하고 최소 scope를 요청하는지 확인하라.
- scope 축소 코드 변경 후 기존 refresh token·동의 grant가 계속 과권한인지 확인하고 재동의·폐기 없이는 수정 완료로 간주하지 마라.
- refresh token 회전·폐기·연동 해제와 계정 탈퇴가 연결되는지 확인하라.
- 공급자 응답의 사용자 식별자를 검증하고 이메일만 신뢰하지 않는지 확인하라.
- 서비스 계정 키 대신 워크로드 신원 등 더 안전한 방법을 우선하는지 확인하라.
- 외부 문서·드라이브 공유 권한이 앱 권한 모델을 우회하지 않는지 확인하라.
- 공급자 장애와 부분 실패가 권한 또는 데이터 불일치를 만들지 않는지 확인하라.

## 18. AI 기능

- 외부 문서·웹·사용자 입력을 시스템 지침과 같은 신뢰 수준으로 처리하지 않는지 확인하라.
- 프롬프트 인젝션이 도구 호출, 비밀 조회, 권한 상승으로 이어지지 않는지 확인하라.
- 모델이 제안한 객체 ID·URL·명령을 서버가 다시 인증·검증하는지 확인하라.
- 모델 컨텍스트와 로그에 개인정보·비밀정보가 과도하게 들어가지 않는지 확인하라.
- RAG 검색이 사용자·테넌트 권한을 보존하는지 확인하라.
- 모델 출력 HTML·Markdown·SQL·코드를 실행하기 전에 정화·검토하는지 확인하라.
- 도구 권한, 비용·토큰 한도, 취소, 속도 제한, 감사 로그를 확인하라.
- 학습·평가·캐시 데이터의 보존과 외부 모델 공급자 정책을 확인하라.
