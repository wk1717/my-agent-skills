# /project-report — 프로젝트 작업 노트

세션 로그를 모아 프로젝트별 노트 한 장을 만든다. 이 노트는 포트폴리오에 옮겨 쓰고, 여러 장을 모아 `/weekly-report`의 입력으로도 쓴다. 그래서 **짧고, 표·불릿 위주이고, 사실만 담는다.**

- 스크립트: `/Users/smk/projects/my-agent-skills/project-report/scripts/collect_sessions.py` (아래에서 `$SCRIPT`)

## 0. 저장 폴더

노트는 **저장 폴더**의 `{프로젝트}.md`로 저장한다. 저장 폴더는 설정 파일(`~/.config/project-report/config.json`)에 들어 있고, 사용자가 다시 바꿀 때까지 계속 그 폴더를 쓴다. 기본값은 `/Users/smk/projects/project-notes`다.

```bash
python3 $SCRIPT --notes-dir                 # 현재 저장 폴더 확인
python3 $SCRIPT --set-notes-dir <경로>      # 변경 (폴더가 없으면 만든다)
```

- `$ARGUMENTS`에 `--out <경로>`가 있거나 사용자가 "저장 폴더를 ~로 바꿔줘"라고 하면 `--set-notes-dir`로 먼저 바꾼다. 바뀐 경로를 한 줄로 알린다.
- 폴더만 바꾸고 프로젝트 이름이 없으면 거기서 끝낸다.
- 폴더를 바꿔도 예전 폴더의 노트는 옮기지 않는다. 옮길지는 사용자에게 한 줄로 묻는다.

## 1. 프로젝트 고르기

`$ARGUMENTS`에 프로젝트 이름이 없으면 목록부터 보여 주고 고르게 한다.

```bash
python3 $SCRIPT --list
```

세션은 로그에 가장 많이 나온 `/Users/smk/projects/<폴더>` 경로 기준으로 프로젝트에 묶인다. 상위 폴더(`~/projects`)에서 열었던 세션도 그 안에서 다룬 프로젝트로 들어간다. 이름은 대소문자를 가리지 않는다.

## 2. 세션 digest 만들기

`{저장폴더}/{프로젝트}.md`가 이미 있으면 **증분 갱신**이다. `--skip-from`에 그 노트를 주면 이미 반영한 세션은 건너뛴다.

```bash
python3 $SCRIPT --project {이름} --out {스크래치패드}/recap-{이름} \
  [--since YYYY-MM-DD] [--until YYYY-MM-DD] \
  [--skip-from {저장폴더}/{프로젝트}.md]
```

세션마다 digest 파일이 하나씩 생긴다. digest에는 사용자 발화(U), 어시스턴트 답변(A), 커밋·설치·배포 명령($), 수정한 파일 목록이 남는다. 커밋 메시지는 그날 한 일을 한 줄로 요약한 것이라 날짜별 로그의 좋은 재료다. `index.md`에는 세션 목록, 크기, 반영한 세션 id가 들어간다.

## 3. 읽고 뽑아내기

`index.md`의 digest 합계를 보고 방식을 고른다.

- **~200KB 이하**: 직접 날짜순으로 읽는다.
- **그보다 크면**: 세션을 날짜순으로 ~150KB씩 묶어 `general-purpose` 에이전트에 병렬로 맡긴다(한 번에 최대 5개). 한 컨텍스트에서 수십 개 세션을 읽으면 앞쪽 세션의 결정과 수치가 흐려지기 때문이다. 에이전트마다 맡은 파일 경로와 아래 추출 형식을 넘기고, 결과를 합친다.

추출 형식(직접 읽을 때도 이 틀로 메모한다):

```
[날짜별] M/D: 그날 한 일 한 줄 (기능·작업 단위, 여러 개면 쉼표)
[기술] 실제로 설치·작성·호출한 것만 — 이름 / 어디에 썼는지
[트러블] 문제 / 검토한 안(A·B…) / 고른 안과 이유 / 결과 수치(원문 표현 그대로) / 근거 파일명
[키워드] 이 작업으로 익힌 개념·기법
```

뽑을 때 기준:
- **트러블**: 사용자가 "왜 안 돼", "에러", "다시", "이게 나아 저게 나아"라고 한 지점과, 어시스턴트가 방안을 비교한 지점에서 찾는다. 오타나 단순 환경 문제처럼 포트폴리오에 쓸 가치가 없는 것은 뺀다.
- **A/B안**: 실제로 검토한 대안만 쓴다. 대안 없이 바로 고친 문제면 A/B 줄을 빼고 "원인 → 해결"만 쓴다.
- **수치**: 세션에 나온 숫자만 쓴다(시간·건수·에러율·토큰·비용·줄 수 등). 면접에서 "그 수치 어떻게 쟀어요?"라는 질문을 받으므로, 지어낸 숫자는 사용자에게 해가 된다. 숫자가 없으면 `정량 근거 없음`이라고 적고 정성적 효과를 한 줄로 쓴다.
- **기술**: 대화에서 언급만 된 것은 빼고, 명령·수정 파일·코드로 실제 사용이 확인된 것만 넣는다.
- **민감정보**: 비밀번호, 토큰, API 키, 고객 이름·연락처는 노트에 옮기지 않는다.
- **무관한 세션**: 세션은 작업 폴더 기준으로 묶여서, 그 폴더에서 연 김에 한 딴 일(다른 저장소의 스킬 정리 등)이 섞일 수 있다. 프로젝트 결과물과 관계없는 세션은 노트에서 뺀다. 다만 session_ids에는 남겨서 다음 갱신 때 다시 읽지 않게 한다.

## 4. 노트 쓰기

`{저장폴더}/{프로젝트}.md`에 아래 틀을 그대로 쓴다. 줄글 문단은 쓰지 않는다. 불릿 한 줄은 80자 안팎으로 쓰고, 트러블은 영향이 큰 순서로 3~7개만 넣는다.

````markdown
# {프로젝트명}

> {무엇을 왜 만들었는지 한 줄}

| 기간 | 세션 | 역할 |
|---|---|---|
| 2026-07-13 ~ 2026-09-15 | 49 (Claude 40 · Antigravity 9) | {1인 개발 / 백엔드 담당 등, 세션에서 확인되는 만큼} |

## 기술 스택
| 영역 | 기술 | 쓴 곳 |
|---|---|---|
| Backend | Supabase (Auth, RLS) | 회원가입·권한 |

## 트러블슈팅 · 의사결정
### 1. {문제를 한 줄로}
- **문제**: {증상 + 원인}
- **A안**: {내용} — {단점}
- **B안**: {내용} — {장점}
- **선택**: B안. {이유 한 줄}
- **결과**: {before → after 수치} *(근거: 09/01 세션)* / `정량 근거 없음` — {정성 효과}

## 키워드
`Playwright 세션 유지` `멱등 처리` `RLS` …

## 날짜별 작업 로그
- 9/01: 쿠팡 로그인 인증 URL 오류 원인 파악, 세션 유지 방식 변경
- 9/02: …

<!-- session_ids: {index.md의 session_ids 그대로, 증분이면 기존 목록 뒤에 추가} -->
````

`날짜별 작업 로그`는 `/weekly-report`의 입력 형식(`- M/D: …`)과 같게 쓴다. 이 섹션만 잘라서 주간보고서에 바로 넣을 수 있다.

**증분 갱신일 때**: 기존 노트는 사용자가 손봤을 수 있으니 통째로 다시 쓰지 않는다. 새 날짜 로그와 새 트러블을 추가하고, 기간·세션 수·기술·키워드는 합쳐서 갱신하고, session_ids는 뒤에 이어 붙인다. 이미 있는 트러블에 새 수치가 생겼으면 그 줄의 **결과**만 고친다.

## 5. 확인과 보고

저장하기 전에 **결과** 줄의 숫자가 digest에 실제로 있는지 하나씩 grep으로 확인한다. 없으면 그 숫자는 지운다.

```bash
grep -rn "{숫자}" {스크래치패드}/recap-{이름}/
```

사용자에게는 짧게 보고한다:
1. 노트 경로, 반영한 세션 수(신규/전체)
2. 한 줄 요약과 트러블 제목 목록
3. `정량 근거 없음`인 항목. 포트폴리오에 수치가 있으면 좋은 항목이면 무엇을 재면 되는지 한 줄로 제안한다(예: "배치 1회 처리 시간을 로그로 재면 before/after가 나옴").
